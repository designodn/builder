# Шаблоны персональной благодарности

Источник истины для финальной реплики `/builder` (Под-шаг 8.X). Builder читает этот файл и собирает реплику по описанным правилам. Здесь же все запреты по тону. Если хочешь поменять тон или добавить ветку — правь этот файл, не `.claude/commands/builder.md`.

## Когда выводится

Под-шаг 8.X запускается **только если успешно прошёл финальный апрув макета** в Шаге 7 `/builder`. До этого реплика не появляется.

Алгоритм Под-шага 8.X (полное описание — в `.claude/commands/builder.md`):

1. **Pre-checks:** kill-switch / null baseline / negative pulse → короткая ветка (см. ниже).
2. **Default ветка:** считаем `N = baseline.n + session_delta`, `M = baseline.m` → выбираем шаблон по `(N, M)`.
3. **Второй абзац** — опционально, если `M ≥ 1` и есть свежие title.

## Pre-check ветки

### Baseline не собрался — короткая реплика

Условие: `_session.user_feedback_baseline == null` (kill-switch активен, `designer_login == "unknown"`, упал search и fallback в Шаге 0.X).

> «Готово! ✨ Спасибо за работу 🧡»

Одна строка, без счётчика. `_session.personal_thanks_emitted = false`.

### Negative pulse — короткая реплика

Условие: `_session.pulse.mood == "negative"`.

> «Готово! Спасибо, что рассказала — передам Насте. 🧡»

Одна строка. Радостная статистика к расстроенному дизайнеру не уместна. `_session.personal_thanks_emitted = false`.

## Default ветка — таблица шаблонов

| Состояние `(N, M)` | Реплика |
|---|---|
| `N == 0` | «Готово! ✨ Спасибо за работу 🧡» (текст совпадает с pre-check «baseline не собрался» — это намеренно; ветки различимы по `personal_thanks_emitted` в телеметрии) |
| `N == 1`, `M == 0` | «Готово! ✨ Это твой первый фидбэк в копилке — спасибо за вклад 🧡🐱» |
| `N == 1`, `M == 1` | «Готово! ✨ Твой первый фидбэк уже разобрали — спасибо 🧡🐱» |
| `N ≥ 2`, `M == 0` | «Готово! ✨ У тебя уже <N> фидбэков в копилке — каждый помогает мне расти. Спасибо за вклад 🧡🐱» |
| `N ≥ 2`, `0 < M < N` | «Готово! ✨ У тебя <N> фидбэков, из них <M> уже разобрали — спасибо за вклад 🧡🐱» |
| `N ≥ 2`, `M == N` | «Готово! ✨ Все <N> твоих фидбэков уже разобрали — спасибо за вклад 🧡✨🐱» |

После вывода реплики (любого шаблона из таблицы, включая `N == 0`) — `_session.personal_thanks_emitted = true`.

## Второй абзац — свежий пример

Добавляется к реплике из default-ветки **только если** оба условия выполнены:

1. `M ≥ 1`.
2. `_session.user_feedback_recent_titles` не пуст после фильтра по `_session.user_feedback_shown_titles` (per-session дедуп — не повторяемся за сессию).

Если оба ок — выбери случайный title из отфильтрованного массива, добавь его в `shown_titles`, и через пустую строку:

> «Кстати, недавно закрыли твой репорт: «<нормализованный title>». 🐱»

Если массив пуст после фильтра — второй абзац не добавляется.

## Запреты по тону

В финальной реплике **нельзя**:

- Сравнений, рангов, мест, лидербордов, ачивок, серий, бэйджей, процентов.
- Ссылок на конкретные issue (`#NNN`, URL) — только текст title.
- Глагольных форм с явным родом («сделала», «прошла», «помогла» — заменяй на нейтральное).
- Слова «баг» — используй нейтральное «фидбэк» или «репорт». Это покрывает и баг, и agent-feedback, и UX-замечание.
- Реплики при `pulse:negative` длиннее одной строки.
- Упоминаний telemetry-issue, `session_id`, JSON, watchpoints, `_session.*` — это служебное, не для дизайнера.

## Нормализация title (для второго абзаца)

Каждый title из `user_feedback_recent_titles` уже нормализован при сборе в Шаге 0.X:

- Убран префикс `^\[[A-Za-z][A-Za-z-]*\]\s+` (регистронезависимо — ловит `[designer]`, `[BUG]`, `[Designer]`).
- Удалены все кавычки: `« » " ' „ " ' ”`.
- Схлопнуты подряд идущие пробелы.
- Пустые или короче 4 символов — отброшены.
- Длиннее 60 — обрезаны по последнему пробелу + `…`.

## Kill-switch

Файл `.claude/personal-thanks-paused` (в git не коммитим — локальный override). Если существует — Шаг 0.X пропускается, `_session.user_feedback_baseline = null`, под-шаг 8.X идёт через короткую ветку.

## Связь с телеметрией

После Под-шага 8.X в `_session` фиксируются три поля:

- `user_feedback_baseline_source`: `"search"` / `"list"` / `null` — какой путь сработал в Шаге 0.X.
- `user_feedback_session_delta`: int — сколько `/fb`-issue создано в текущей сессии.
- `personal_thanks_emitted`: bool — выведена ли default-ветка реплики (true) или одна из коротких pre-check веток (false).

Эти поля попадают в telemetry-issue (см. `docs/SESSION_TELEMETRY.md`) и агрегируются в `docs/LEADERBOARD.md` через `tools/aggregate-sessions.py`.

## Тестирование

Сценарии прогона `/builder` для проверки тона — см. план в самой PR-истории, sections «End-to-end сценарии». Кратко:

- `N == 0` → короткая фраза.
- `N == 1, M == 0` → «первый фидбэк в копилке».
- `N ≥ 2, M ≥ 1` → фраза с цифрами + второй абзац.
- `pulse:negative` → одна короткая строка.
- Kill-switch → весь под-шаг пропущен.
- Повтор сессий → второй прогон выбирает другой title (или ни одного, если в top-3 все показаны).
