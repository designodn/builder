# Чеклист оптимизации токенов

Адресован разработчику (Насте). Не должен попадать в runtime-контекст builder-агента.

**Цель:** минимизировать токены за полный цикл (бриф → CJM → layout.json → Figma).

После каждого изменения, которое затрагивает вызовы Claude API, выполни ревью по чеклисту. Не коммить, пока ревью не пройдено.

## Prompt caching

- [ ] Статичные части системного промпта (каталог, схема, секции `rules/`) передаются с `cache_control: { type: "ephemeral" }`
- [ ] Переменные данные (промпт пользователя, текущий CJM) — в `messages`, не в `system`
- [ ] После вызова логируются `cache_creation_input_tokens` и `cache_read_input_tokens`

## Размер промпта

- [ ] Каталог фильтруется по релевантности (не весь реестр огульно). Для рантайма — читать `registry/index.json` (derived cache из rules); для детальных пропов конкретного компонента — `rules/components/<slug>.rule.json` лениво, только когда компонент попал в layout.
- [ ] `rules/*.md` грузятся посекционно, не весь `rules.md` целиком
- [ ] В промпт не попадают поля компонентов, которые модель не использует
- [ ] `max_tokens` под реальный максимум ответа, не с запасом

## Архитектура вызовов

- [ ] Один агент — один вызов API
- [ ] `researchOutput` и план шага 6 не пересчитываются между шагами — передавать через контекст
- [ ] Промежуточные результаты (отфильтрованный каталог) не запрашиваются у модели повторно

## Качество вывода

- [ ] Промпт требует строгого формата (JSON без markdown-обёртки)
- [ ] Схема layout.json без избыточных комментариев

## Как проверить

1. Запусти `npm run agent:build -- --prompt "тестовый экран"` с реальным API
2. Посмотри токены: `cache_write`, `cache_read`, `input`, `output`
3. `cache_read = 0` на повторе → caching не работает
4. `input_tokens > 3000` → лишнее в промпте
