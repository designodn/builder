# Подключение Котика-Ботика — инструкция для дизайнера

Привет! Тебе открыли доступ к **Котику-Ботику** — агенту-помощнику, который собирает макеты в Figma по компонентам нашей дизайн-системы. Этот гайд проведёт от «мне прислали приглашение» до «я нарисовала первый макет».

Время на всё про всё — 10-15 минут, в основном на установку.

---

## Что ты получаешь

- **Доступ на чтение** к репозиторию `kotik-botik/kotik-botik` — клонируешь, открываешь в Claude Code, читаешь любые файлы.
- **Право создавать issues** в этом репо — туда уходят твои сообщения о багах через скилл `/fb`.
- **Самого Котика-Ботика** — он живёт прямо в репозитории как набор инструкций для Claude Code. Открыла репо → Котик-Ботик автоматически встречает тебя приветствием.

## Что недоступно (это специально)

- Редактировать файлы и пушить изменения — GitHub физически откажет (роль Read).
- Запускать `/test`, `/syncKeys`, `/parseProps` — это служебные скиллы Насти. Котик-Ботик откажется их выполнять.

Все твои локальные правки **не сохраняются** на GitHub. Это нормально: твоя работа сохраняется в **Figma**, а не в репо. Перед каждой сессией запускай `/update`, чтобы получить актуальный реестр компонентов и стереть локальные правки.

---

## Шаг 1 — Принять приглашение в репо

1. Открой почту → найди письмо от GitHub: «You've been invited to collaborate on kotik-botik/kotik-botik».
2. Нажми **Accept invitation**.
3. Готово — теперь репо доступен на чтение в твоём GitHub-аккаунте.

Проверить можно так: `github.com/kotik-botik/kotik-botik` должен открываться без 404.

## Шаг 2 — Установить Claude Code

Котик-Ботик работает **только** в Claude Code (десктоп или CLI). Веб-чат `claude.ai` не подойдёт — там нет инструментов для Figma.

- **Десктоп (рекомендую):** https://claude.ai/download — Mac или Windows.
- **CLI:** `npm install -g @anthropic-ai/claude-code` (нужен Node.js).
- **Claude Code on the web:** https://claude.ai/code — работает, но ограниченнее. Если не получается поставить десктоп — этот вариант пойдёт.

После установки войди в свой Claude-аккаунт.

## Шаг 3 — Подключить GitHub к Claude Code

Чтобы Claude Code мог клонировать репо и создавать issues:

1. В Claude Code открой **Settings → Integrations → GitHub → Login**.
2. Авторизуйся через свой GitHub-аккаунт.
3. На странице установки GitHub App выбери: **доступ к организации `kotik-botik`** (или конкретно к репо `kotik-botik/kotik-botik`).
4. Подтверди.

Проверка: в Claude Code → Open Repository — в списке должен появиться `kotik-botik/kotik-botik`.

## Шаг 4 — Открыть проект

В Claude Code → **Open Repository** → выбери `kotik-botik/kotik-botik`. Клонирование начнётся автоматически.

Если работаешь через CLI:

```bash
git clone https://github.com/kotik-botik/kotik-botik.git
cd kotik-botik
claude
```

Через несколько секунд после первого сообщения **Котик-Ботик сам тебя поприветствует** и покажет список доступных команд. Это нормально — он перехватывает первое сообщение и показывает приветствие независимо от того, что ты написала.

## Шаг 5 — Подключить Figma MCP

Чтобы Котик-Ботик рисовал макеты, нужен доступ к Figma через MCP. Это разовая настройка на устройство:

1. Напиши Котику-Ботику: `/connectFigmaMCP`.
2. Он проведёт через установку токена Figma шаг за шагом.
3. Когда закончит — тест-вопрос «всё работает?», ответь как есть.

## Шаг 6 — Подтянуть свежее состояние и начать

```
/update
```

Этот скилл подтягивает актуальный реестр компонентов и правила. Запускай в начале каждой сессии.

```
/builder
```

Это основной скилл — собрать макет в Figma. Котик-Ботик задаст уточняющие вопросы про твою задачу, при желании подключит экспертов (аналитик, продакт, поиск похожего опыта), построит маршрут пользователя (CJM), и после твоего апрува нарисует макет.

---

## Что делать, если что-то сломалось

Запусти `/fb <что произошло>`. Котик-Ботик задаст пару уточняющих вопросов, сам соберёт технический контекст (этап работы, имя компонента, состояние реестра, последняя ошибка Figma) и создаст issue в репозитории — туда Настя смотрит регулярно.

Можно и без команды — просто напиши «слушай, я наткнулась на…», и Котик-Ботик сам предложит зафиксировать.

### Типичные случаи

| Симптом | Что писать |
|---|---|
| Компонент не нашёлся в реестре | Сначала `/update` (вдруг устарел), потом если всё ещё нет — `/fb` |
| Figma ругается на импорт | `/fb` — лейбл `bug:import-failed` Котик-Ботик поставит автоматически |
| Макет собрался криво | `/fb` — опиши что не так |
| Нужен компонент, которого нет в библиотеке | `/fb` — «нужен новый компонент X» |

### Чем подробнее — тем быстрее починим

В `/fb` укажи:
- что делала (например, «попросила собрать форму логина с двумя кнопками»);
- что ожидала;
- что получилось;
- ссылку на Figma-файл, если есть;
- скриншот, если уместно.

## Шпаргалка по командам

| Команда | Что делает | Когда |
|---|---|---|
| `/update` | Подтянуть свежий реестр и правила | В начале каждой сессии |
| `/builder` | Основной флоу: бриф → CJM → макет | Когда хочешь нарисовать макет |
| `/fb` | Зафиксировать баг или пожелание | Когда что-то идёт не по плану |
| `/connectFigmaMCP` | Подключение к Figma | Один раз на устройство; повторно — если перестало работать |
| `/about` | Подробно про проект | Когда интересно, что вообще тут есть |

## Часто задаваемые вопросы

**Можно ли коммитить мои изменения?**
Нет. У тебя роль Read — GitHub откажет в push. Это специально: вся твоя работа сохраняется в Figma, а не в коде. В репозитории живёт только дизайн-система (правила компонентов, реестр), которой управляет Настя.

**Я случайно поменяла файл локально. Как откатить?**
`/update` — он сделает `git reset --hard origin/main`. Если есть локальные правки, Котик-Ботик сначала переспросит подтверждение.

**Котик-Ботик не находит нужный компонент. Это баг?**
Скорее всего, реестр у тебя устарел. Сначала `/update`, потом, если всё ещё нет — `/fb`.

**Можно ли запустить `/test`, `/syncKeys` или `/parseProps`?**
Нет, это служебные скиллы Насти. Котик-Ботик откажется. Если думаешь, что они нужны — `/fb`, лейбл `feedback:ux`.

**Котик-Ботик иногда переключается на холодный, странный тон. Это нормально?**
Да. Это GLaDOS-режим — Котик-Ботик включает его, когда видит попытку редактировать защищённые файлы или просьбу повысить доступ. Тебя это касаться не должно: на разрешённых действиях (`/builder`, `/update`, `/fb`, вопросы) тон остаётся обычным, тёплым. Если кажется, что он включил GLaDOS зря — `/fb feedback:ux`.

**К кому идти, если совсем непонятно?**
К Насте напрямую (Telegram). Через `/fb` — только воспроизводимые проблемы. Вопросы по продукту и непонятки — лично.
