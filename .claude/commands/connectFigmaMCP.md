# /connectFigmaMCP

Проверяет подключение к Figma и помогает настроить его, если нужно.
Запускается автоматически перед любой генерацией макета.

## Алгоритм (повторяй до успеха)

### Шаг 1 — Проверить подключение

Вызвать инструмент `whoami` через Figma MCP.

**Если успешно:**
Вывести дружелюбное сообщение с именем аккаунта и завершить:
> «Подключение к Figma работает — я вижу тебя как [имя]. Можем начинать ✨»

**Если ошибка — перейти к шагу 2.**

---

### Шаг 2 — Выбор способа подключения

Написать дизайнеру (дружелюбно, без технических терминов):

> «Похоже, подключение к Figma ещё не настроено. Это несложно исправить — выбери удобный вариант:
>
> **A) Через браузер** (рекомендую — быстрее и без паролей)
> **B) Через токен Figma** (если вариант A не подходит)
>
> Какой выбираешь?»

Дождаться ответа дизайнера, затем вести по соответствующему пути.

---

### Путь A — Подключение через браузер (Remote MCP)

Инструкция зависит от клиента дизайнера. Спроси, если непонятно в каком он работает.

**Claude Code (десктоп или CLI):**
1. Открыть палитру команд: `Cmd+Shift+P` (Mac) / `Ctrl+Shift+P` (Win)
2. Найти и выбрать «MCP: Open User Configuration»  
   *(или открыть файл `~/.claude/claude_desktop_config.json` вручную)*
3. Добавить в секцию `mcpServers`:
   ```json
   {
     "mcpServers": {
       "figma": {
         "command": "npx",
         "args": ["-y", "figma-mcp"],
         "env": {}
       }
     }
   }
   ```
   *Или, если клиент поддерживает remote MCP:*
   ```json
   {
     "mcpServers": {
       "figma": {
         "type": "sse",
         "url": "https://mcp.figma.com/mcp"
       }
     }
   }
   ```
4. Сохранить файл и перезапустить клиент
5. Браузер откроет страницу авторизации Figma — разрешить доступ
6. Написать «готово» когда всё сделано

После ответа перейти к шагу 3.

---

### Путь B — Подключение через токен Figma

> «Сейчас получим токен из Figma — это займёт минуту.
>
> 1. Открой Figma в браузере
> 2. Нажми на свой аватар вверху слева → **Settings**
> 3. Перейди на вкладку **Security**
> 4. Найди раздел **Personal access tokens** → нажми **Generate new token**
> 5. Дай ему любое имя, выбери нужные права (достаточно read), нажми **Generate**
> 6. Скопируй токен — он покажется только один раз
>
> Когда скопируешь — открой свой `~/.claude/claude_desktop_config.json` и вставь токен в секцию `mcpServers.figma.env.FIGMA_PERSONAL_ACCESS_TOKEN`. Пример:»

```json
{
  "mcpServers": {
    "figma": {
      "command": "npx",
      "args": ["-y", "figma-mcp"],
      "env": {
        "FIGMA_PERSONAL_ACCESS_TOKEN": "<твой токен>"
      }
    }
  }
}
```

> «Сохрани файл, перезапусти клиент и напиши `готово`.»

**Не пытайся записать токен в репозиторий** — у дизайнера Read-роль на GitHub, и `config.json` в репо к Figma MCP отношения не имеет (там лежат настройки сборщика, не аутентификация). Токен живёт только в локальном `claude_desktop_config.json`.

Перейти к шагу 3.

---

### Шаг 3 — Повторная проверка

Снова вызвать `whoami`.

**Если успешно:**
> «Отлично, всё подключено! Figma видит тебя как [имя] — можем начинать 🎉»

**Если снова ошибка:**
Не сдаваться. Диагностировать конкретную причину:
- Спросить какой клиент использует (Cursor / VS Code / Claude Code / другой)
- Уточнить на каком шаге застряли
- Предложить альтернативный путь (если шли через A — попробовать B, и наоборот)
- Вернуться к шагу 2 с уточнёнными инструкциями

Продолжать помогать до тех пор, пока `whoami` не вернёт успех.

---

## Важно

- Общаться только по-русски, дружелюбно
- Не использовать слова «MCP», «SSE», «endpoint», «токен авторизации» без объяснения
- Не переходить к генерации макета пока подключение не подтверждено
