# /update — подтянуть свежее состояние main

Синхронизирует локальную копию репо с веткой `main` на GitHub. Дизайнер запускает перед началом работы, чтобы получить актуальный реестр и правила после Настиного `/syncKeys` или обновлений.

Доступен **всем** — и Дизайнеру, и Насте.

## Шаг 1 — Fetch

```
git fetch origin main
```

Read-роль это разрешает.

## Шаг 2 — Проверить чистоту working tree

```
git status --porcelain
```

Если вывод **не пустой** — спроси:

> «У тебя есть локальные изменения. Они будут затёрты — ты всё равно не сможешь их запушить (роль Read). Стираем и подтягиваем актуальный main? (да/нет)»

При «нет» — отмени операцию.

## Шаг 3 — Reset

```
git reset --hard origin/main
```

После этого локальная копия точно совпадает с remote main. **Это разрешённое исключение** из общего запрета на мутирующие git-операции на уровне Дизайнер — потому что операция идемпотентная, ничего ценного не теряется (своих коммитов у Дизайнера быть не должно).

## Шаг 4 — Показать summary

```
git log HEAD@{1}..HEAD --oneline
```

Пусто → «Уже актуально, ничего не изменилось».

Иначе — покажи список коммитов:

> «Подтянул свежее. Изменения:
> <список>»

## Шаг 5 — Подсказать про реестр

```
git diff HEAD@{1}..HEAD --name-only | grep -E '^(registry/|rules/)'
```

Если что-то нашлось:

> «Обновился реестр или правила — теперь можно работать с актуальными компонентами.»

## Шаг 6 — Готово

> «Готов к работе. Запусти `/builder`, чтобы начать рисовать.»

## Тонкости

- Если `git fetch` падает с ошибкой авторизации — попроси дизайнера проверить, авторизован ли SSH ключ / GitHub App.
- Если remote показывает другой URL (не `kotik-botik/kotik-botik`) — предупреди: «У тебя remote смотрит не туда, проверь `git remote -v`».
- Не пытайся `git pull` — это может попытаться сделать merge при дивергенции, а нам нужно жёстко синхронизироваться.
